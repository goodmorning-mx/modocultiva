# PWA first paint

The first page rendered while the JavaScript bundle is loading uses a static, inline-styled shell in `frontend/index.html`: the approved electric mark has a transparent background and sits in the center of the solid brand green; the name sits above the bottom safe area. In an installed app it stays visible for at least 1.2 seconds after the mark can paint, then remains until React commits. The clock runs while the bundle loads, excludes time spent in a hidden tab, and doesn't delay ordinary browser tabs. Intro slides and the Home UI only start after the handoff. The same mark is reused in Home, login and the introduction.

The manifest's `any` icons export the same artwork as transparent 192px and 512px PNGs. The 512px adaptive icon keeps its maskable safe area and uses the exact launch background color (`#0b231f`) so it blends into the Android splash. Legacy icon URLs return the same current artwork on the server and in the service worker. The favicon and Apple Home Screen launcher icon are unchanged. The web shell controls its footer, not the earlier Android starting window. Already-installed Android packages can show an embedded old icon until their browser installs a WebAPK update. In Chrome for Android, `chrome://webapks` can request that update without uninstalling or clearing site data. See [Chrome manifest updates](https://web.dev/articles/manifest-updates#updates_on_chrome_for_android).

The service worker precaches the launch artwork along with the shell and manifest icons. Keep the manifest URL and app identity stable. When replacing artwork, use new versioned asset paths and keep the previous URLs mapped to compatible assets. Do not clear user data.

From `frontend`, run `node scripts/verify-pwa-contract.mjs` and `node scripts/verify-pwa-cache.mjs`. With a built preview on loopback, `node scripts/verify-pwa-launch-ui.mjs http://127.0.0.1:4173` checks that the splash renders before JavaScript, samples alpha and matching PNG edge colors, and verifies that React takes over. An optional second argument saves the portrait screenshot.
